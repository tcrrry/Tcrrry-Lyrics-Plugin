# 歌词排版、缓存与更新过渡预览

2026-10-14；独立插件 `1.0.7-preview.4` / versionCode 26。未发布正式版，暂不覆盖主项目安装包。

## 排查到的问题

- RubyWordLayout 的旧算法先最小化行数，再均衡每行留白，并惩罚单字末行。因此确实会出现未填满当前行就换行，而不一定是歌词源原有断句。
- 自动歌词缓存仍存在，FileAutoLyricsCache 原上限为 2GB。但读取适配层在 qualityFirst 或 smoothShortUnits 开启时直接返回 null；smoothShortUnits 默认开启，使通常设置下的磁盘缓存一直无法命中。
- 同曲刷新会清空自动指针，旧指针仅在刷新失败后恢复。新结果即使与旧 TTML 相同也重新解析生成指针，触发宿主整页重装。
- 原生歌词到达还会重复刷新自动结果，包括已有逐字缓存的情况。

## 本轮修复

- 完整发音单元尽量占满当前行后再换行，不均衡上下行长度；保留源歌词段落及原生计时单元，不为凑行拆分单元或缩小字体。过长的完整发音单元仍可能让行尾留白，这是对齐约束，不承诺所有行贴满。
- 用实际设置指纹校验缓存，不以质量优先/短单元平滑开关直接禁止缓存。指纹覆盖来源/选中记录/排除记录/偏移、匹配优先级、平滑、译文设置、日语注音及强调状态；保留语言注音标记与未完成补译校验。设置变化或缺少新版指纹的旧缓存会重新生成一次，不删除手动文件。
- 请求开始时记录设置指纹与清理代次；过时请求不能把错误设置结果写回渲染缓存。
- 同曲更新期间保留可用旧指针；TTML 相同（忽略缓存指纹注释）时复用指针，避免重复解析/装载。不同内容准备好后才替换。
- 原生逐行歌词到达不再丢弃已经准备好的逐字替代，也不重启正在进行的自动查询；原生逐字/明确原生优先仍按原有优先级处理。查询结束时读取最新原生歌词，避免错过迟到的逐行兜底。
- 同曲必须重装的可见计时歌词页，用旧内容快照与新页做 240ms 交叉淡化，旧快照轻微模糊。仅作用于歌词列表，不改播放控制、字体或列表位置。快照最多 524288 像素；关闭系统动画时直接更新。换歌、失效、离开页面、插件关闭或 700ms 兜底会清理遮罩并恢复透明度。

## 缓存设置

“更多工具 → 歌词缓存”：0–1024MB，16MB 步进，默认 64MB；最大显示为 1GB。0 不保存磁盘歌词缓存，内存中的当前显示不消失。

共同计入上限的是当前自动 TTML 文件和自动生成的匹配历史 payload。读取会更新最近使用时间；超额时删除最久未使用的文件，不停止保存新歌词。降低容量后后台立即收缩。

“清理歌词缓存”清这两类磁盘文件；统计和删除放在后台线程。它不删除手动导入歌词、设置、离线语言模型、词典、搜索索引、翻译缓存，也不强制刷新当前页面。内存中正在使用的歌词仍可显示，后续新查询可能重新生成缓存。补充译文仍使用原有独立清理选项。

## 验证与边界

新增测试覆盖：首行填满而非均衡、默认平滑与质量优先缓存命中、设置变更失效、清理后旧请求不能回写、0/1GB 限制、按最近使用淘汰、手动文件/模型保留、刷新期间旧指针可用、相同 TTML 不重解析、新译文就绪后替换、原生迟到不丢逐字缓存、过渡完成/失效/无 pre-draw 的清理以及设置入口。

Robolectric/构建/导入检查不等于实机动画验收。需要手机验证窄行/长发音单元、A→B→A（及重启应用后）的缓存表现、切换来源和补译/注音的转场、缓存滑块及清理。首次升级到新版指纹的旧歌词仍可能重新匹配一次；逐行缓存可先显示再尝试升级逐字，不承诺所有重播都零网络。

实机确认后再迁移主项目；迁移必须保留已验证的共存路由和 vivo 服务发现声明，不能用旧正式宿主清单重新打包而丢掉播放器修复。主项目所有安装形式应使用相同插件 versionCode 26，并按各自验证边界记录结果。
