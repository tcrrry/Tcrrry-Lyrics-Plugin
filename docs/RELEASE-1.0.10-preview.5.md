# 1.0.10-preview.5 — 单曲循环与间奏跳转

- 补上 ViewModel 结果通道缺失的独立播放进度观察。旧方案的 NativeLyricsImmediateAnchor 处于互斥分支，其循环/跳转观察此前没有迁入新通道；模糊层只知道高亮行，间奏/尾奏无法依赖这条回调触发恢复。
- 由已验证当前歌曲的 MediaBrowser 采样进度，500ms 检查播放跳变，持续播放不反复重绑或重装歌词。即使尾奏没有原生歌词事件，回到开头也能重新评估原生歌词处理器并恢复首行跟随。原生 Handler 继续按其事件延迟运行。
- 间奏中点击进度条，不再要求先存在高亮行。只读原生 SongInfo sections/lines 的时间：有歌词则定位当前行，间奏定位下一句，尾奏保留最后一句。没有新建、平移或伪造字词计时。
- 暂停时跳进度也能更新歌词并定位，不启动音频或强行恢复播放；暂停时的小幅前跳单独识别。
- 拖动/惯性滚动、隐藏或无窗口焦点时延后恢复；投递布局定位后再次校验歌曲、指针、页面和请求版本。停用/视图销毁取消观察和过期布局动作，同歌指针更新不丢失循环检测。
- 仅新结果通道启用，独立于可选模糊/聚焦模块。不恢复旧的直接 Fragment 重装、轮询强制锚定、原生时间参数篡改。
- 保留 preview.4 高亮门恢复、触摸监听保护与精简，五字来源按钮、当前窗口内刷新、三种语言注音排版/字号/顺序/原生换行以及原生译文优先策略不变。

验证涵盖无高亮回调的尾奏循环、间奏前后跳转、暂停跳转、同歌更换指针、拖动延期、异歌拒绝及停用后布局任务取消。手机已连接但未导入新包；真实播放需手动导入确认。
