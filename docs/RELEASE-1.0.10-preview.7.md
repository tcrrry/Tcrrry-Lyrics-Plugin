# 1.0.10-preview.7 — 跳进度时的原生动画竞态

- preview.6 在同一帧提交退出与进入，RecyclerView 可能合并两次更新，省略中间过渡；现在按“原生结束旧动画与清理持有项 → 退出旧句 → 独立布局帧 → 原生动画完成 → 进入最新目标 → 新布局后恢复逐字事件”执行。
- 观察当前 MediaBrowser 的公开 seekTo(long)/seekTo(int,long)，覆盖播放中小幅前跳，不再只依赖 500ms 轮询的 1500ms 跳变阈值。60ms 合并连续拖动请求，等待播放器时钟接近目标；轮询保留为单曲循环与外部进度变化兜底。
- 旧设备日志出现过约 250ms 的回退也触发恢复。播放中的轮询回退不足一秒时不重开动画；明确的 seekTo 事件仍处理小幅前后跳转。
- 跳转期间只暂停歌词处理与当前歌词适配器的更新，音频不暂停、不自动播放。旧动画取消时释放的过期行回调不能覆盖新目标；完成后短期校验原生行回调携带的媒体时间，拒绝明显属于旧进度的任务。
- 每次跳转重算当前时刻的已唱字快照，保留跨视觉行的高亮恢复。间奏定位下一句，暂停跳转、单曲循环、日语/韩语/粤语排版、注音字号、原文/发音/译文顺序及原生换行保持原有行为。
- 页面失焦、手势、视图销毁、停用插件或迟迟没有完成回调时，释放歌词处理门并恢复原生事件，不把宿主永久留在暂停更新状态。所有新增观察与拦截均经 SDK hooks 注册，停用清理。

验证新增跨帧退出/进入、小幅播放中跳转、连续跳转仅采纳最后目标、过期原生行回调拒绝、过渡期逐字处理阻断、失焦恢复和新钩子清理，并回归单曲循环与暂停定位。只修改歌词插件，不修改宿主或主项目。桌面测试与原生接口验证不能代替新包导入后的真机动画验收。
