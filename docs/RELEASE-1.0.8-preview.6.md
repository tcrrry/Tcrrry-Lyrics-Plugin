# 1.0.8-preview.6 本地预览

## 从逐条词表改为署名区块分析

不是“全文包含冒号就删”，也不是再补一批职位名。已有角色作为署名区的识别依据；连续开头区域有至少两条明确署名时，未收录的“字段名：内容”也可纳入区块，前面漏掉一个新乐器不会让后面整段已知署名失效。未知字段数量不再限制为三行，也不强制要求它们每行三秒内结束。

没有足够证据时，单条明确且带内容的署名仍可隐藏，未知内容保留。未开始正文的未知字段可以位于已知署名前面。重复的未知文本按可能的演唱内容保护，正文开始后不再继续扫描删除。

## 不依赖冒号

支持已知职责后的空格、连字符、斜杠、下划线、括号与中点，例如“作词 张三”“作曲-李四”“编曲（王五）”“录音师/李四”；支持英文 Produced/Mixed/Performed by 等署名。

兼容多字中文职责后的未知英文别名，不再要求英文别名也出现在词表中。全半角和外层括号先归一化。职责独占一行、姓名在下一行的格式可成对识别，但需要整块明确证据，不因为出现单独的 Music 和后续英文短句就删掉它们。

## 正文保护与边界

男/女/合/旁白等声部，以及“你说：”“He said:”等对白不会作为字段署名；未知字段直接连接对白或重复歌词时会保守回退。没有署名依据的普通冒号句不删；短行或快速行不是独立删除条件；全是署名的响应保留，不生成空歌词。

所有识别都是文本启发式，不能保证任意格式零误删或零漏删。特别是只有孤立人名、既无职责也无分隔符的文本，仍不凭字数强行隐藏。原始歌词缓存保留，过滤开关关闭即可恢复原文。播放、预览使用同一策略，时间不平移。
