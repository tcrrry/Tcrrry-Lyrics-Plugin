# 1.0.8-preview.7 本地预览

## 署名遗漏的实际原因

这次不是继续补职位词。QQ《画中来》（mid `001eIB8D1u7OiJ`，musicid `502768038`，250 秒）的 QRC 原始文本包含“词：曹韵/刘思情@骁Studio”，但冒号、斜杠和 @ 的逐字时长为 0。转换器不为这些零时长字符生成演唱跨度，之前又用演唱跨度重建文本来判断署名，所以过滤器看到的是已经失去标点的“词曹韵刘思情骁Studio”。这也解释了补了职位以后仍反复遗漏的现象。

现在每个逐字行另保留不丢标点的原始文本，用它判断开头署名区块，并用于版本预览。正文的逐字渲染、起止时间、发音和翻译对齐保持原逻辑，不为零时长标点伪造发音时间。QQ 和网易云经过相同转换器，修复同时适用。即使只有缓存的逐字轨、没有独立逐行轨，也能工作。

已更新渲染缓存指纹，旧的未过滤 TTML 不会继续命中；原始来源缓存、手选版本和偏移不删除。开关关闭仍恢复未过滤内容。过滤策略仍有保守边界，不承诺所有未知格式都能识别。

实际 QRC 的标题、14 行署名和两句正文保存在测试样本 `opening-credits-qq-hua-zhong-lai.qrc`。同一份源数据在改动前能复现过滤失败，改动后播放转换及预览都从 19470ms 的第一句正文开始。对白“我说：”、声部“男：”另有零时长标点保护测试。

## 中文歌冷启动的方形菜单入口

1609 原始 APK 的 `fragment_player_lyrics_sheet` 将 `translations_button` 默认为 GONE；`PlayerLyricsViewFragment.F2` 又按是否有真实翻译/发音决定 GONE 或 VISIBLE。此前仅在 onCreateView 返回和 onResume 结束后登记按钮，初始化期间的原生条件分支没有被覆盖。

现在仅对精确 7.0.0-beta / 1609，在 `q8.X4` 原生绑定构造完成时登记实际 `o0: ImageView`，早于页面的观察者和控制动画初始化。只覆盖这个已登记按钮的 GONE，不拦截 INVISIBLE、不全局强制所有控件可见，不伪造翻译/发音可用状态。沉浸隐藏、页面销毁及插件停止仍释放或恢复原生状态。1606 继续用已验证的原路径。

新增原生 APK 字段/构造静态校验，以及冷启动登记、沉浸隐藏、无关控件、销毁和停止恢复测试。电脑测试并不等于手机实际冷启动验收；本次尚未获得连接设备。
