# 1.2.1-preview.1

本地修复预览，基于 1.2；没有发布 GitHub，也不修改 AM++ 宿主包。

## 修复

- 原生歌词中多个演唱者的独立段落不再使整首歌的发音突出功能失效。保留段落演唱者、对齐属性、原生时间轴与译文。
- 背景和声、缺少段落时间的复杂段落保留原样，只转换具备完整信息的主唱段落，不再因一处不支持而禁用整首歌。仅有复杂背景段落、无可转换发音时仍保持禁用。
- 菜单在后台准备完成后同步发音突出可用状态；点击读取当前设置，弹窗移除后取消偏好监听。
- 原生逐字行的机翻、平台译文与发音辅助行跟随原行的左、右、居中对齐；复用同文案行时也更新。逐行模式同步主歌词的对齐方式，释放辅助布局时恢复状态。

## 作者库和宿主歌词设置

插件把 Zennmn/am-lyrics 作为独立 `am-lyrics` 来源，菜单显示“AM++ 作者整理库”，按歌曲 ID 获取。不是把作者库当作 Apple Music 官方原生歌词。

自动选择由 NativeLyricsPreferencePolicy 与 AutoLyricsSourceResolver 仲裁：真正原生逐字歌词通常优先；未选定来源时，作者库也可能被自动选中。明确选择作者库时只请求该库。

AM++ 宿主自己的手动歌词、自动补词和翻译仍有独立提交路径。HostLyricsSubmissionGuard 只保护插件已经准备好的相同指针免于宿主二次改写，并不关闭宿主所有补词。宿主先行替换的文档也可能被下游看到，因此两个模块都对同一首歌指定替换时仍应避免重复管理。需要插件统一选源时，可在宿主设置停用相应的手动映射、自动替换及重复翻译功能，保留插件的设置；本预览没有代改宿主配置。

## 纯音乐反馈分析（本次未改）

1. 第三方按元数据匹配到二创版本，是候选选择错误，不能仅靠“AM 没歌词”认定其为纯音乐。
2. AutoLyricsReplacementSession.refreshCurrent 备份旧结果，readyReplacementFor 在新来源无结果时继续返回备份；当前提示“保留当前歌词”与代码一致，旧误匹配因此可能保留。
3. 双击当前源可排除已显示的平台记录；该功能不等于禁止这首歌的全部第三方歌词。
4. 建议增加按歌曲保存的“不使用第三方歌词／按纯音乐显示”，把明确拒绝与暂时未找到分开，清理备份、缓存及对应的外部歌词输出。新请求失败时仍可保留用户未拒绝的正确歌词。
5. 播放页空白而词幕有旧词，说明至少有一条显示或输出路径未同步清理；具体旧数据来自宿主、插件、词幕缓存还是其独立歌词源，需要复现确认。
6. 原生翻译在词幕缺失是另一条辅助轨导出问题。应在相同歌曲下对照插件启用前后的主词、翻译输出；不能从截图认定是翻译被删除。

本地单测、Lint、构建与 PluginStore 导入结果在本次验证日志中。实际手机排版、发音切换效果待覆盖导入复测。
